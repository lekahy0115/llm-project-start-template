# Google Colab에서 `.ipynb`로 서비스 시연하기

## 서비스 노트북이 맡을 역할

`notebooks/service/`에 실제 기능에 맞는 `.ipynb` 파일을 만들고, Colab 런타임에서 다음 순서를 실행합니다.

```text
서비스 노트북 시작
  → 필요한 라이브러리·모델 로드
  → Google Drive 데이터/가중치 접근
  → 사용자 입력 수신
  → LLM 추론 처리
  → 결과 표시
  → (필요한 경우) 외부 접근 주소 공유
```

서비스 노트북 이름 예: `RENAME_ME_service_demo.ipynb`. 프로젝트 기능이 정해진 후 실제 이름으로 만들며, 위 과정은 아직 구현되어 있지 않습니다.

## 가능한 서비스 구성

- **Gradio 방식:** 노트북에서 입력 폼과 결과 화면을 띄우는 시연 방식입니다. 프로젝트에 맞게 구현해야 하며, 공유 링크 사용 가능 여부와 보안 정책을 확인합니다.
- **FastAPI + ngrok 방식:** 노트북에서 웹 서버를 실행하고 외부 터널로 접속하는 시연 방식입니다. 사용자 인터페이스는 별도로 구성할 수 있습니다.

둘 중 어느 기술도 미리 강제하지 않습니다. API 사용 여부, GPU 필요량, 인증 요구 사항은 구현할 때 결정합니다.

## GitHub·Drive의 역할

- **GitHub:** 서비스 노트북 자체를 팀 작업 브랜치에서 작성·검토·병합합니다.
- **Google Drive:** 모델·원본 데이터·추론 산출물 등 용량이 큰 파일을 저장합니다.
- **Colab:** 노트북 코드를 실행하고 모델 추론·웹 서버/화면을 구동합니다.

GitHub에 서비스 노트북을 Commit해도 웹 서버가 자동으로 실행되지는 않습니다. 시연할 때 Colab에서 해당 노트북을 **직접 실행**해야 합니다.

## 시연 시 주의사항

1. 서비스 노트북은 `main`에 병합된 버전을 기준으로 실행합니다.
2. 외부 공개 주소가 생성되면 허가되지 않은 사람이 접속할 수 있습니다. 비공개 데이터·관리 기능을 노출하지 않습니다.
3. ngrok 인증 토큰과 기타 비밀키는 코드 셀이나 출력에 남기지 않습니다.
4. Colab 런타임 사용 시간이 끝나거나 세션이 끊기면 서비스도 중지됩니다. 이는 24시간 운영용 배포가 아닌 **프로젝트 시연 방식**입니다.
5. 영구 배포가 필요하면 나중에 서비스 코드와 실행 환경을 분리할 수 있습니다. `.py` 기반으로 옮길 때에도 현재 노트북과 데이터·협업 구조를 참고하여 확장할 수 있습니다.
